## Материалы для защиты

В [модели угроз](THREAT_MODEL.md) выбран приоритетный набор; каждая его угроза связана с SR и решением, содержащим будущую проверку. Пример для объяснения: [T-03](THREAT_MODEL.md#t-03) → [SR-06](SECURITY_REQUIREMENTS.md#sr-06) → [D-02](DESIGN_DECISIONS.md#d-02). Разбор учитывает разные жалобы на один материал, конкуренцию и частичный сбой. Планы в D ещё не выполнены.

Перед сдачей команда должна:

1. Подтвердить фактический вклад каждого M1–M3 в [CONTRIBUTIONS.md](CONTRIBUTIONS.md). Сейчас сведения о распределении работы не предоставлены, файл этого не скрывает.
2. Подтвердить статус ранней калибровки; в исходном паспорте он остаётся «черновик».
3. Проверить обязательный комплект по регламенту курса, включая актуальность существующей декларации [AI_USAGE.md](AI_USAGE.md). Этот файл в изменениях S03–S05 не редактировался.
4. Выбрать commit из принятой версии, получить его командой `git rev-parse HEAD` и передать URL репозитория вместе с этим hash преподавателю к объявленному сроку. Создание PR само по себе не является сдачей. После сдачи продолжать работу следующими коммитами, не заменяя оцениваемую версию.
5. Воспроизвести запуск выбранной версии на компьютере для демонстрации и самостоятельно объяснить цепочку и свой вклад на защите без ИИ.

Техническая основа и проектные цепочки подготовлены; перечисленные командные действия не подтверждаются автоматически наличием файлов и тестов.
