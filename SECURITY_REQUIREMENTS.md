# Риски и требования безопасности

Проект: **«Разбор жалоб на контент»**. Основа: [паспорт проекта](PROJECT.md), OWASP Top 10:2025 и OWASP ASVS 5.0.0. Это проектные риски и требования к будущей реализации, а не результаты проверки работающего сервера. Продукт — REST API с локальной SQLite-базой, подготовленными учебными аккаунтами и каталогом материалов; отдельного пользовательского интерфейса, загрузки файлов и внешних интеграций нет.

## Риски по OWASP Top 10:2025

| Категория | Сценарий риска в проекте и последствия |
| --- | --- |
| **A01 Broken Access Control** | Пользователь подставляет ID чужой жалобы в запрос просмотра и узнаёт автора и причину обращения; либо вызывает действие модератора и скрывает материал без полномочий. |
| **A02 Security Misconfiguration** | При запуске API вне локальной разработки остаются включены отладочный режим или служебные `/docs` и `/openapi.json`, если они предназначены только для команды. Посторонний получает сведения о внутренних маршрутах или диагностике. |
| **A03 Software Supply Chain Failures** | При сборке устанавливается подменённая либо уязвимая версия FastAPI, SQLAlchemy или другой зависимости из незафиксированного источника. Она получает доступ к аккаунтам, жалобам и решениям в процессе сервера. |
| **A04 Cryptographic Failures** | Пароли заранее созданных аккаунтов сохраняются в SQLite или исходных данных открытым текстом либо быстрым хешем. Утечка файла базы позволяет восстановить пароль модератора и действовать от его имени. |
| **A05 Injection** | Причина жалобы или параметр фильтра попадает в SQL-запрос как часть строки. Атакующий меняет запрос и читает чужие жалобы либо изменяет данные. |
| **A06 Insecure Design** | Два модератора одновременно рассматривают одну ожидающую жалобу. Без правила единственного перехода оба решения сохраняются, а статус жалобы и состояние материала расходятся. |
| **A07 Authentication Failures** | Для входа в заранее созданный аккаунт модератора можно неограниченно подбирать пароль. После успешного подбора злоумышленник получает право решать жалобы и скрывать материалы. |
| **A08 Software or Data Integrity Failures** | При первоначальном заполнении базы приложение принимает изменённый набор учебных аккаунтов и материалов как доверенный. Подмена роли аккаунта на `moderator` или исходного статуса материала искажает права и решения системы. Этот риск относится к этапу загрузки начальных данных, если он реализован через внешний файл. |
| **A09 Security Logging and Alerting Failures** | Решение модератора меняет состояние материала, но приложение не фиксирует исполнителя, жалобу, время и результат. Позже невозможно установить источник неправомерного скрытия; повторные отказы в доступе и попытки входа остаются незамеченными. |
| **A10 Mishandling of Exceptional Conditions** | После записи решения возникает ошибка при скрытии материала или фиксации статуса жалобы. API возвращает ошибку, но частичные изменения остаются в базе: жалоба удовлетворена, а материал всё ещё доступен, либо наоборот. |

## Требования безопасности

`SR-*` задают обязательное свойство и критерий приёмки. Ссылки ASVS указывают на применимые пункты стандарта и не утверждают соответствие всему уровню ASVS. Для каждого критерия проверяется также состояние базы после отказа или ошибки.

| ID | Требование | Критерий приёмки | Связь с OWASP |
| --- | --- | --- | --- |
| **SR-01** | API разрешает пользователю читать только собственные жалобы; решение по жалобе и скрытие материала доступны только модератору. Сервер проверяет роль и право на выбранный объект при каждом запросе. | Пользователь Б запрашивает жалобу А по её ID и вызывает маршрут принятия решения: оба запроса отклонены, данные чужой жалобы не раскрыты, статус жалобы и материала не изменён. А видит свою жалобу; модератор может выполнить разрешённое действие. | A01; ASVS `v5.0.0-8.2.1`, `v5.0.0-8.2.2`, `v5.0.0-8.3.1` |
| **SR-02** | В режиме, предназначенном для использования вне локальной разработки, диагностический вывод отключён, а служебная документация API доступна только по явно принятому решению команды. | При запуске в таком режиме запрос к `/docs` и `/openapi.json`, если эти маршруты не объявлены публичными, не возвращает схему API; ошибка запроса не раскрывает стек вызовов или параметры конфигурации. | A02; ASVS `v5.0.0-13.4.2`, `v5.0.0-13.4.5` |
| **SR-03** | Состав сторонних библиотек и разрешённые источники их получения зафиксированы; известные уязвимости зависимостей рассматриваются до использования версии в сборке. | Для сборки доступен список библиотек с версиями и источниками. Сборка из подменённого источника либо с версией, нарушающей документированный срок устранения уязвимости, не принимается. | A03; ASVS `v5.0.0-15.1.1`, `v5.0.0-15.1.2`, `v5.0.0-15.2.1` |
| **SR-04** | Пароли учебных аккаунтов в хранилище представлены стойкими адаптивными хешами; открытые пароли не входят в исходный код, файл начальных данных, ответы API и журналы. | При осмотре файла SQLite и данных для развёртывания пароль модератора в открытом виде отсутствует. Вход с верным паролем проходит, с неверным — отклоняется; в ответах и журналах пароль не появляется. | A04; ASVS `v5.0.0-11.4.2`, `v5.0.0-13.3.1` |
| **SR-05** | Любой клиентский ввод, участвующий в выборе или изменении записей, передаётся в запрос к БД как данные, без изменения структуры запроса. | Причина жалобы или параметр запроса с SQL-метасимволами сохраняется или отвергается по правилам поля; чужие жалобы не возвращаются, другие записи и схема БД не изменяются. | A05; ASVS `v5.0.0-1.2.4` |
| **SR-06** | Жалоба может перейти из ожидания только в одно окончательное состояние. Запись решения и, при удовлетворении жалобы, скрытие материала составляют одну атомарную операцию. | Два одновременных решения по одной жалобе приводят ровно к одному сохранённому решению; второй запрос отклонён. Статус жалобы и материала соответствуют сохранённому решению. | A06; ASVS `v5.0.0-2.3.3`, `v5.0.0-15.4.2` |
| **SR-07** | Вход в аккаунты, включая модераторский, защищён от перебора пароля. Правило ограничения попыток и период восстановления документируются для учебного развёртывания. | После установленного лимита неверных попыток дальнейший вход для атакуемого аккаунта временно ограничен; верный пароль во время ограничения не даёт обойти его, а в журнале видны неудачные попытки. | A07; ASVS `v5.0.0-6.3.1`, `v5.0.0-16.3.1` |
| **SR-08** | Если начальное заполнение БД выполняется из файла, приложение принимает только доверенный набор данных с проверенной целостностью и допустимыми значениями ролей и статусов; при провале проверки не создаёт рабочую базу из частичного набора. | Изменение роли пользователя или статуса материала в файле без обновления доверенного подтверждения целостности вызывает отказ загрузки. После отказа в БД нет частично добавленных аккаунтов или материалов. | A08; ASVS `v5.0.0-14.2.4` — применимо к проверке целостности только после фиксации класса защиты начальных данных по `v5.0.0-14.1.2` |
| **SR-09** | Приложение фиксирует решения модератора и неуспешные попытки доступа с исполнителем, объектом, временем и результатом; записи защищены от изменения через обычные маршруты API. Команда задаёт способ просмотра этих событий, чтобы можно было заметить повторные отказы. | После принятия или отклонения жалобы доступна запись с ID модератора, ID жалобы, временем и результатом. После отказа в чужом запросе видна запись отказа без текста чужой жалобы. Пользователь не может изменить эти записи через API. | A09; ASVS `v5.0.0-16.2.1`, `v5.0.0-16.3.2`, `v5.0.0-16.3.3` |
| **SR-10** | При ошибке записи решения, статуса жалобы или состояния материала операция целиком отменяется; клиент получает безопасный ответ об ошибке без внутренних деталей. | Искусственная ошибка БД между шагами рассмотрения возвращает отказ. В БД остаются исходные статус жалобы и состояние материала, нового решения нет; ответ не содержит SQL-запроса, трассировки или секрета. | A10; ASVS `v5.0.0-2.3.3`, `v5.0.0-16.5.1`, `v5.0.0-16.5.3` |

## Границы и дальнейшая проверка

- `SR-02` касается только запуска за пределами локальной разработки: в текущем паспорте продукт предполагается локальным, поэтому это условие не означает уже запланированное публичное развёртывание.
- `SR-08` проверяется, если для начального заполнения используется отдельный файл; при ином способе загрузки нужно уточнить доверенную границу и критерий, сохранив ID и смысл свойства.
- К S03 следует уточнить способ входа, лимит попыток, защиту начальных данных и способ просмотра событий. Работающий сервер и готовые автоматизированные тесты для S02 не требуются.
